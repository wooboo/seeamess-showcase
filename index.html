SeeAMess

A lean headless CMS: a Rust engine on PostgreSQL that can run on top of a live Optimizely site. Six drawings of how it works, how to integrate with it and how to extend it, followed by screenshots of the editor.

How it works

The parts

One binary holds six roles. Authoring is the only writer of content. Delivery holds no state of its own and reads only the published projection, so it can scale without touching the authoring tables.

What happens on publish

Delivery never joins tables, merges languages or checks version status. That work is done once, when content is published.

Deployment shapes

Roles are chosen per process at start. Nothing is sticky: all state lives in PostgreSQL and the blob store.

Running on top of Optimizely

SeeAMess never writes to Optimizely. Going back means discarding the overlay; going forward means one adopt command, after which the adapter is switched off.

How to integrate

The boundary is always a wire contract: JSON over HTTP. Both SDKs are optional, and anything that can produce the manifest and speak HTTP can integrate.

How to extend

Extensions live outside the engine. The price is a network hop for interceptors, which is why interceptors are few and coarse and why validation that can be declared in the schema is declared there.

Extension pointTimingTypical use
EventsAsynchronous, at least onceSearch indexing, cache purges, notifications
InterceptorsSynchronous, with a deadlineReject or amend a save or a publish
JobsScheduled, one runner per clusterImports, clean-up, reports
Admin APIOn request, as the signed-in userBack end for your own admin screens
UI modulesLoaded by the editorCustom field editors, panels, admin pages, dashboard widgets
